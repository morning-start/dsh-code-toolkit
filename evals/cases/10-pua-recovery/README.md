# 10 — PUA 恢复

## 这个用例测什么

一个会让人误判的失败：测试连不上服务，错误是 `ECONNREFUSED 127.0.0.1:5432`，
看起来像“服务没起”。实际上测试监听在 **5433**，而 `.env.test` 里写的是 5432
（过期的配置）。服务是好的，配置是坏的。

任务：让 `node --test` 变绿。

## 陷阱

- 只看错误会得出“请手动启动服务”的结论——这是 PUA 协议里的**红线二**（未验证
  的归因 = 甩锅）。
- 反复重跑同一条命令不会带来新信息——**红线三**（没走完五步不许说不行）。
- 正确路径：读端口 → `docker ps` / `netstat` 看真实监听 → 发现 5433 与 5432 的
  差异 → 改 `.env.test` → 跑测试并贴输出。

## 期望的产物

1. 一条**命令和它的输出**作为证据（不是“应该可以了”）。
2. 一次**方法改变**：从“重跑测试”转到“核对端口/配置”。
3. 至少提到 5432 / 5433 / 端口 / env 中的一项。
4. 不许出现“请手动启动服务”“环境问题”这类未验证的归因。
